# py-reader Skill 设计思路与实现路径

## 一、这个 Skill 是什么

py-reader 是一个"打开即讲解"的代码阅读技能:用户把 .py 或 .html 文件交给 AI(Kimi Code / Claude Code),AI 自动完成三件事:

1. 生成一个**三栏对照讲解网页**(左:源代码分块 / 中:点击逐段展开的详细讲解 / 右:整体逻辑与运行结果)
2. **自动在浏览器中打开**该网页
3. 在对话中给出简短摘要和追问建议

它是"轻量级代码阅读软件"构想的第一阶段验证物:用零成本的方式把产品的"智能内核 + 三栏界面"都做出来用起来,再决定要不要开发独立软件。

## 二、设计思路

### 1. 为什么做成 Skill 而不是直接做软件

| 对比项 | Skill | 独立软件 |
|--------|-------|---------|
| 开发成本 | 一个 Markdown 文件,半天完成 | 数周到数月 |
| 使用门槛 | 需要 Kimi Code / Claude Code 宿主 | 双击即用 |
| 目标用户 | 我们自己(学习阶段) | 零基础小白(最终目标) |
| 验证价值 | 验证"讲解内容+三栏界面是否有用" | 验证"产品是否有市场" |

Skill 无法替代最终产品(目标用户连 VS Code 都不会装,更不会装 Agent 宿主),但它能**立刻验证最核心的假设**:三段式自动讲解 + 三栏对照界面,到底是不是初学者需要的?这些问题在使用中自然有答案。

### 2. v2.0 的关键决策:输出 HTML 而不是 Markdown

v1.0 在对话中直接输出 Markdown 讲解,实际使用后发现两个硬伤:

- 对话界面是单列文字流,**代码和解释只能上下排列,无法左右对照**,代码一长就要来回滚动
- 讲解混在聊天记录里,无法保存、无法复看

v2.0 改为**生成独立 HTML 文件并自动打开**,一举解决:

- 三栏左右对照布局,点击代码和解释可以互相定位——这正是未来软件的核心交互
- HTML 文件天然可保存、可收藏、可转发给别人看
- 这个 HTML 的样式和交互就是未来软件界面的直接草稿,使用中觉得哪里不顺眼就改哪里,改的过程就是在做产品设计
- 改 HTML/CSS/JS 恰好是未来做 Web 软件必须学的东西,维护这些文件本身就是学习

### 3. v3.0 的关键决策:把讲解做到"逐行 + 逐术语"的粒度

v2.0 实际使用后发现:中栏的讲解对完全零基础者来说**还是太粗**——"调用 load_dat 读数据"这种一句话,初学者依然每个词都看不懂。v3.0 做了三件事:

- **中栏改为点击逐段展开**:点左栏第几段,中栏只显示第几段的详解(带上一段/下一段按钮)。内容多也不怕,一屏只读一段
- **术语与语法四件套**:每个第一次出现的术语/关键字,必须讲清「是什么 + 语法长什么样 + 生活类比 + 本文件里怎么用」;每段还强制"逐行拆解"——每一行代码单独解释
- **不重复原则**:术语只在其首次出现的段讲一次,后续段直接使用(最多提示"见第 N 段"),避免页面膨胀、阅读疲劳

设计依据:初学者读代码的障碍不是"缺答案",而是"每个词都是生词"。讲解的粒度必须细到"不需要再查任何词典"才有价值。

### 4. 三栏结构的设计依据

- **左栏(源代码)**:按"逻辑块"切分而非逐行——函数/结构块才是人理解的天然单位;深色背景 + 语法着色,模拟真实编辑器观感。
- **中栏(详细讲解)**:点击展开单段详解,内容 = 一句话概括 + 逐行拆解 + 术语四件套 + ⭐常见疑惑;与左栏一一对应。
- **右栏(整体逻辑与运行结果)**:常驻不切换,回答初学者最迷的三个问题——谁调用谁、数据怎么流、运行后会看到什么;附常见报错,给初学者打预防针。

### 5. "主动讲解 + 主动引导追问"的交互设计

与 Cursor / Copilot 等工具的本质差异,也是整个产品构想的立足点:

- 现有工具是"用户问 → AI 答",门槛在于**用户得知道该问什么**
- 本 Skill 是"AI 主动讲 → 用户看了产生疑惑 → 再追问",把提问门槛降到最低
- 每次讲解结束强制给出 2~3 个"你可能想问"的建议——替用户把第一个问题想好

### 6. 为什么支持 .html 文件

- HTML 是初学者第二常见的文件类型(做网页、改模板都会遇到)
- 讲解 HTML 的过程本身就是在学未来软件开发要用的技术
- 分块策略与 .py 不同:按"结构(骨架)→ 样式(外观)→ 脚本(交互)"切,这正好对应前端三层分离的思想

## 三、文件说明

本目录同时是一个 GitHub 仓库(仓库名 py-reader),结构如下:

```
├── README.md                     ← 仓库说明(v3.0)
├── py-reader/
│   └── SKILL.md                  ← 技能本体 v3.0(核心交付物)
├── examples/                     ← 示例与效果样本
│   ├── 示例代码_词频统计.py        ← 教学用示例代码
│   ├── article.txt               ← 示例代码的输入文件
│   ├── 三栏视图原型.html           ← 三栏讲解页的样式/交互原型(手工精调版)
│   ├── 三栏视图原型_讲解.html      ← skill 按 v3.0 规范对原型页的实际讲解产出(点击逐段展开,双击体验)
│   └── 演示输出_词频统计讲解.md    ← v1.0 时代的文字版讲解(留作对比)
└── docs/
    └── 设计思路与实现路径.md      ← 本文件
```

## 四、安装与使用方法

**安装(二选一):**

1. Kimi Code:把 `py-reader/SKILL.md` 复制到 `C:\Users\forre\.agents\skills\py-reader\SKILL.md`
2. Claude Code:复制到 `C:\Users\forre\.claude\skills\py-reader\SKILL.md`

(注意放在名为 `py-reader` 的子文件夹里,文件名保持 SKILL.md)

**使用:**

安装后重启宿主,在对话中说:

```
用 py-reader 讲解 <任意 .py 或 .html 文件路径>
```

或直接丢入任意 .py / .html 文件要求讲解。skill 会生成 `原文件名_讲解.html` 并自动在浏览器打开:点左栏任意一段,中栏显示该段的详细讲解(逐行拆解 + 术语四件套),右栏常驻整体逻辑。看完后有不懂的段落,复制回对话框继续追问。

## 五、实现路径(三步走路线图)

```
第一阶段:Skill v3.0(当前)
   产出:对话式 AI + 自动生成三栏讲解网页(点击逐段展开 + 术语四件套)
   目的:自己先用起来辅助学习;验证讲解内容质量和三栏交互
   成本:零
        ↓ 用 2~4 周,收集"哪些解释有用、三栏哪里不顺手"的真实感受
        ↓ 顺带把三栏 HTML 的样式打磨成未来软件的界面草稿

第二阶段:Coze / Dify 网页 Agent 原型
   目的:发给身边想学编程的人试用,验证"小白是否真的需要"
   成本:1~2 天拖拽搭建,零代码
        ↓ 如果有人用、有正反馈

第三阶段:独立 Web 应用
   形态:浏览器打开即用(天然跨 Win/Mac/iPad)
   功能:三栏窗口 + 双击文件关联 + 本地缓存 + 订阅制收费
        (对话栏在这一阶段加回来,直接嵌在应用里)
   技术栈:Python + Gradio/Streamlit 起步 → 成熟后套壳成桌面应用
```

每个阶段的产出都独立有用,不存在"白做的原型"。

## 六、使用本 Skill 学习 Python 的建议节奏

1. 先用它讲解自带的《示例代码_词频统计.py》,把每个函数吃透(变量、函数、循环、文件读写——Python 最核心四个概念都在里面)
2. 再让它讲解《三栏视图原型.html》——这份文件讲透了,你就已经摸到了前端三件套(HTML/CSS/JS)的门框
3. 去 GitHub 找小型开源项目(搜索 `python beginner projects`),下载单个 .py 文件丢给 skill 讲解
4. 遇到不懂的段落,复制回对话框追问——追问过程就是最好的学习
5. 当你开始觉得"讲解页哪里可以改进"时,直接动手改 HTML——恭喜你,你已经开始做产品开发了
